# Problems Solved

## Tags not showing for signed-in users

**Symptom:** Blog cards rendered correctly but tags were always empty for signed-in users.

**Root cause:** `blog.id` stored the RSS `guid` (an externally-controlled string) as the primary key. Guid format varies by feed — Dropbox uses full URLs, others use arbitrary strings or numeric IDs. This made `blog.id` and `blog_tag.blog_id` inconsistent, causing the `LEFT JOIN` to return NULL for `blog_tag.blog_id` and the `IN` filter in `list_by_blog_ids` to match nothing.

**Fix:**
- `blog.id` → `UUID` generated by us, reliable PK
- `blog.guid` → `Text`, stores RSS guid, `UNIQUE` constraint for dedup on ingest
- All FK columns (`blog_chunk.blog_id`, `blog_tag.blog_id`, `blog_prerequisite.blog_id`) reference the UUID

**Lesson:** Externally-controlled, format-inconsistent values should never be used as primary keys or foreign key anchors.
