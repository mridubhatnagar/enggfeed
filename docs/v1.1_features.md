# V1.1 Features

---

## Remove Search

Search removed entirely — UI, backend wiring, `search/` module, `blog_chunk` table, and `ingest/chunker.py` all deleted.

**Why:** Tag + company filtering covers the primary discovery use cases. Search is not a meaningful feature for a curated blog aggregator.

---

## Multi-Select Company + Topic Filters

Replace the company dropdown and single tag filter with a two-row pill browser supporting multi-select.

### UX
- Two-row filter strip on page background (no heavy bar)
- **Company row** — horizontally scrollable pills, multiple selectable
- **Topic row** — horizontally scrollable pills with article counts, multiple selectable
- Active pills highlighted in indigo
- Filters combine as: blogs matching **any selected company AND any selected topic**
- Company + Company = OR, Topic + Topic = OR, Company + Topic = AND

### Backend changes
- `BlogDAO._build_query` — `IN` clause for sources and tags instead of `=`
- `BlogDAO.list_blogs` / `count_blogs` — accept `list[uuid]` for sources and tags
- `BlogService` — update signatures accordingly
- `BlogHandler` — resolve multiple source/tag names to IDs
- `GET /api/v1/blogs` — accept comma-separated `source` and `tag` query params

### Frontend changes
- Remove search bar and all search-related JS
- Add two-row pill filter strip — sticky below navbar (`position: sticky; top: 60px`)
- Multi-select state for company and topic pills
- Pass comma-separated selected values in API calls
- Update URL sync to handle multiple values

---

## Infinite Scroll

Replace pagination buttons with infinite scroll on the feed.

- `IntersectionObserver` on a sentinel element at the bottom of the feed
- On sentinel visible, fetch next page and append to the blog list
- Show a loading spinner while fetching
- Stop observing when all pages are loaded
- Filter strip is sticky so filters remain accessible while scrolling

**Why moved from v2:** Becomes more valuable as the corpus grows. Pairs naturally with the sticky filter strip — users can scroll freely and adjust filters at any point without losing their place.

## Preserve Filters on Back Navigation

When navigating back from Summary or Simplify to the feed, restore the active company and topic filters instead of resetting to the feed root.

- Pass active filters into the navigation state
- `goFeed()` restores filters from state rather than clearing them

## Empty State for Filtered Feed

Show a helpful message when a Company + Topic filter combination returns no results.

- "No articles found for the selected filters"
- Include a "Clear filters" button to reset both company and topic selections

## Expandable "+N more" Chips

Make the "+N more" chip on cards actionable instead of decorative.

- Clicking "+N more" expands the chip row inline to show all tags/prerequisites
